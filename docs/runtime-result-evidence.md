# Runtime result evidence

The four business tools add `result_evidence` and `evidence_summary` to their final authorized results. Both representations derive from the same public object, after privacy and authority projection. Existing result facts, observation times, references and lifecycle records retain their meaning. The metadata grants no authority and does not validate an external client's final prose.

| Result family | Supported observation | Limit |
| --- | --- | --- |
| Action/resource/settings catalog | Actual returned metadata count; complete or partial enumeration of the authorized catalog query | No source inventory, eligibility decision or Runner work inventory; pagination is not a cross-page snapshot |
| Source rows | Actual serialized row count and existing reviewed query facts | Population completeness remains unestablished; business flags do not inspect requests, approvals or queues |
| Aggregate groups | Actual disclosed group count and existing authorized measures | Withheld values are not zero and omitted groups do not establish a complete source total |
| Semantic request | Existing disclosable approval, execution, disposition and invocation/replay facts for one request | Creating or replaying a request is not another applied effect or a queue-wide inventory |
| Agent settings | Permitted settings or a disabled revision receipt | Settings, control references and historical receipts do not establish activation or business execution |
| Refusal/unavailable/unknown | Safe explicit diagnosis or unknown coverage | A failure is not an empty successful result, proof of absence or proof of no effect |

Opaque source references identify scoped lookups. Issuance proves neither human intent, eligibility, approval, execution nor a stable later snapshot. The ordinary request checks remain authoritative. A fresh `request_change` can create work and must not be used as a harmless status probe. Use existing permitted request status or an authorized application/operator surface for facts the returned query did not assess.

The optional generated integration instructions recommend useful supported observations, scoped counts and honest unknowns. They do not overwrite third-party global prompts. Customer selection and status presentation remain client responsibilities, `verified:false`.

## Implementation and bounds

`packages/mcp-server/src/result-evidence.ts` declares the finite four-tool/fourteen-family contract and exhaustive interpretation. Unknown root envelopes receive unknown semantics. Row and database/model text cannot select a trusted family. Metadata requires no additional source or store read and adds no response-generation timestamp. Reserved presentation fields are rebuilt from the authorized host envelope.

The compact authoring emitter and pretty compatibility emitter decorate their final public results before serialization. Catalog packing and session accounting measure the decorated text and structured representations, retaining the existing entry, response and cumulative caps. A complete contract that no longer fits inline uses the existing exact-detail route; it is never truncated and called complete. Source query `returned.bytes` and `max_response_bytes` retain their existing data-array contract; presentation overhead is separate, not a redefinition of that budget.

Existing declared output schemas accept the typed optional metadata. Named legacy tools outside the four-tool surface are unchanged. Tests execute actual SDK/producer paths as well as finite presentation controls; derived responses remain labelled. The normal full suite includes the result-evidence tests. No new status endpoint, fifth tool, hidden count, private eligibility filter or queue grant is introduced.

## Client reporting

Report the useful visible facts and returned count. Qualify completeness by the actual query and observation. Say when a requested fact was not assessed. Keep pending approval, approved/queued, application, replay and unknown outcomes separate. Runner does not receive or validate an external model's free-form answer; deterministic summaries are evidence-scoped guidance, not a certificate for extra prose.
