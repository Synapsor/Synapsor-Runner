# Saved review pause: traced cause and bounded design

On the unchanged old installed tree, recommended Resume selected the exact saved five-day Action candidate and paused with zero provider sends. Source, consent, chat and model session were present. The owned instrumented copy shows `reviewCompiledSourceCounters -> currentPolicyCoverageDraft -> inspectedReadScopes` throwing `POLICY_RLS_EVIDENCE_STALE` before `ensurePreparedPolicyCoverage` or a provider request. Its catch records a source-counter detail, returns undefined, and `reviewActiveActionRules` returns false; `pauseAttachedRules` hides that actual prerequisite failure behind a generic pause. This is not a model failure or a missing policy decision.

`inspectActionProject` intentionally merges reader metadata with separately inspected writer posture for Action compilation. Its reader and merged schema fingerprints and selected Read lock all agree; its merged role fingerprint is the writer fingerprint, not the exact reader fingerprint pinned by the Read lock. Passing that combined inspection as policy-review reader evidence is the first wrong association. The strict RLS validator correctly refuses it and will remain unchanged. Explicit saved Review has the same inspection call and must use the same correction.

Evidence: raw `diag-A/operator-captures/terminal-001.log` is the unchanged public run; `terminal-002.log` and `terminal-003.log` are labelled owned-copy instrumentation. The initial and expanded instrumentation records are retained. Neither original installation nor original stopped project was run writable. Full matching restored source/control baseline and effective-store preflight are in `diag-A/RESTORE-VERDICT.json`.

Design: acquire fresh source inspection through the selected Read generation lock's existing reader environment, separate from Action's writer-enriched inspection. Use this common source preparation in guided post-save/Resume and explicit saved Review, including source-counter proof checks. Keep exact schema/role/lock validators, counter commitments, prepared review producer/parser, current-context checks, existing coordinated saves and reuse validation. Provider work remains outside coordination. No authority/policy/source/identity change is made by inspection. A real prerequisite error must appear in the first pause notice with an actual review/revalidation next step, not a spurious business edit. Cancellation must remain cancellation.

No business worker, request, activation or provider transport occurred in these diagnostic runs. Application-state differences from ordinary checkpoint saves will be reported, not called whole-ledger byte identity.
