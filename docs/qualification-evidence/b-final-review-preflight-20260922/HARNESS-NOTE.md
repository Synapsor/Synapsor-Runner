# Qualification harness contract

This is test infrastructure, not product authorization. It never changes Runner's resolver, current authority, TTL, approval or execution behavior. Use the existing frozen installation and existing provider meter. The independent tester owns the new public Review.

`phase_environment` constructs a child environment from an explicit reviewed map, not the shell. Authoring gets reader plus optional funded provider; MCP gets reader; verifier gets reader/writer; worker gets writer; administrator gets administrator. Reviewed local tenant/principal context is retained where required. Only authoring may add the exact pinned meter import. Unknown references (including PGPASSFILE/PGSERVICEFILE/BASH_ENV) refuse before child launch. Role classification must be checked against the actual selected config; labeling an administrator URL “reader” is not proof of its privilege.

`audit_mounts` rejects host-root/home/runtime-directory mounts and examines every fixture/config/helper file for forbidden credentials, auto-load files, IPC and symlink escapes. Explicit OS roots are read-only trusted prerequisites. Exactly `.env.example` is a non-autoload template and remains content-scanned; the independent tester found this necessary for the unchanged project and package. No archived or installed file was removed. `bubblewrap_args` starts with fresh temporary/runtime namespaces and explicit target parents. Caller closes inherited file descriptors and scans full URL plus credential components, so hiding an administrator password in a different file cannot pass by deleting only an env name. The manifest must name every mount. This is a bounded local test process contract, not a general sandbox/security claim.

`sqlite_snapshot` reads all discovered tables including sqlite_sequence under one read transaction; no writable database open. Blobs retain exact bytes. `config_tree_snapshot` discovers all files and symlinks each time; callers separately identify exact database/log exclusions, including why those are covered elsewhere. It detects newly added files. Complete source inventory/column/row export comes from the existing fixture-owner read-only exporter. `compare_snapshots` reports all membership, metadata and content deltas, preserving duplicate-row multiplicity. It never treats an expected table name as permission for arbitrary changes. Private snapshot files contain full records; public summaries contain counts, paths and hashes only. Separate store/source reads are not an atomic cross-store snapshot.

Source receipt hashing retains ordinary JSON serialization property order. Canonical control receipt hashing sorts keys. Neither an equal count nor applying one hash method to both receipts is sufficient. The original failed main source-hash calculation remains preserved in the previous task and was corrected there without a runtime rerun.

`require_prepublication_observations` checks a particular live PID/start-token/session against completed listing/detail/read observations; `require_replay_time` refuses a schedule that cannot fit inside genuine reference lifetime plus its margin. They are rehearsed guards for a future explicitly authorized lifecycle controller, not evidence that historical missed observations happened. No publication, request or worker is run to test them here.
