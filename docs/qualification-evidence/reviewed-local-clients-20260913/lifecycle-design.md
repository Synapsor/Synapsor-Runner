Named references are local-development operator configuration, never model arguments or authentication. Keep the existing default `.synapsor/local-test-runtime.json` behavior compatible. A named profile has a constrained operator label and an exact immutable reviewed identity revision. Its generated launcher selects that revision, with the existing canonical project/Read identity contract, binding allowlist, owner/private-file checks and environment mismatch refusal. No label or revision enters policy deployment, ledger resolution, canonical accounting selectors or business authority.

Before persistence or installation, the operator reviews the named identity locally with hidden value collection, project/identity contract and shared deployment, then explicitly confirms. Decline/cancellation leaves previous entries and authority unchanged. A second named entry does not replace the default or another named entry. Replacing values creates a new exact reviewed revision; an old launch reference never resolves to new values. Use explicit stop/relaunch to switch a client. Reference lifecycle and client-file mutations must be serialized and detect failed/concurrent writes without losing another entry.

Retirement is explicitly **future-launch retirement**, using existing managed entry removal plus a retained retired-reference marker. It refuses new launches/reselection of that reference. A process already holding validated identity retains its context until the operator stops it; do not advertise immediate revocation. This bounded operation does not require or promise remote session tracking. Existing admitted/dispatched requests and history are unchanged. No cancellation/refund/requeue is implemented by profile management. If safe minimal persistence/selection cannot honor this contract without a general session service, preserve the dependency and stop that branch.
