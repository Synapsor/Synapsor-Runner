# P1 blocked closure implementation

Product/tests: ae96fb0b2556cb2b9465adfc796fee76389f2eb9, following initial repair 4bff1ba831904f94b1b36f9f9f735aa9616b61d7. Baseline: 4b22b460d80eaa246ad4fd0928dc541a49833c81. Runtime tools and business/accounting queries are unchanged.

Historical W2 does not contain enough producer evidence. Its zero-effect receipt and safe error were synthesized after an adapter error; they did not durably identify acknowledged rollback or the source endpoint. The independent challenge established this missing provenance. Historical W2 stays unavailable and is never executed here.

The new PostgreSQL source_db producer emits `synapsor.postgres.source_db.rollback.v1` only after ROLLBACK acknowledgement, for semantic v5 stale-authority failures. COMMIT/ROLLBACK uncertainty, applied results and unsupported modes do not emit it. The normalized canonical job digest covers the entire atomic target set. The new record contains a credential-free source/receipt-namespace digest. The trusted host adds current execution configuration, writer environment NAME, existing apply roles and the actual lease/attempt/store binding. It persists `writeback_source_rollback` with the unchanged failed receipt in one existing control transaction. There is no retroactive migration or parallel evidence ledger.

The shared assessment requires exactly one resolved attempt, matching canonical receipt/job/proposal/idempotency record, the authorized/claimed/job/failed/blocked event lineage, no live lease, no outstanding admission or intent, exact repository/deployment/project identity and a nonempty recorded apply-role set. An explicitly recorded cancellation control role also applies. A read-only lookup at the bound ordinary non-RLS receipt table must find no receipt. Current business rows are not inspected as historical proof. Missing source access, applied/in-progress/contradictory receipts, ambiguous histories and unsupported modes refuse.

Human and JSON commands use the same assessment. `worker close-blocked` defaults to preview and a default-cancel confirmation. Existing signed-key/JWT authentication must satisfy current configured apply authority and the recorded attempt role(s). The signed decision's existing reason binds the complete assessment and operator reason. No local actor label, model argument or trusted worker identity substitutes for that operator.

Source inspection and authentication finish before acquiring the control writer lock. The normal runtime admission gate protects configuration resolution; no control-store writer transaction or authority mutex is held during source I/O, signing or human confirmation. PostgreSQL source inspection uses connection 3s, statement 3s and query 4s limits. The final transition uses existing SQLite BEGIN IMMEDIATE or native PostgreSQL schema advisory writer coordination; its exact current control state is reassessed. There is no database distributed transaction. The prior producer proves transaction finality, while the source lookup checks for contradiction against that immutable attempt.

A one-row conditional update changes only the worker item from blocked to discarded, terminal_outcome discarded, and update time. The failed proposal, original approval, job, attempts and canonical receipt stay intact. One `writeback_blocked_closed` event records actor, reason, evidence and no refund. The existing queue cannot dispatch discarded or blocked items. A repeat/lost-acknowledgement replay must match the original accepted digest, source observation and reason and returns that durable result. Failed event persistence rolls back the update. PostgreSQL binds its real repository and checks actual native admission state under its writer transaction before using the shared primitive; bridge identity is ephemeral, not a new policy copy.

Failed proposals were already excluded from the active-subject duplicate lookup. Closure does not add a bypass. Old references keep their old failed result; new references read current facts and obtain independent approval. Closure does not require the old Action to be active. A fresh request does. The actual accounting evaluator continues to count the retained automatic approval for tenant and boundary limits at both exhausted and available capacity; no successful-execution accounting is introduced.

The supported envelope is deliberately narrow: one attempt, v5 PostgreSQL, source_db/precreated explicitly qualified ordinary receipt table, nondelegated semantic stale refusal, producer proof and reviewed nonempty apply roles. Unknown/multiple/legacy attempts, delegated dispatch, handlers/MySQL/Runner-ledger, missing role/provenance, URL options that prevent exact endpoint binding and uninspectable/filtered receipts remain unavailable. All cooperating workers must use the new producer for future failures to qualify. No arbitrary clock-skew, multi-host, universal exactly-once or compensation claim is made.

Named failed development attempts remain in the raw root: baseline harness normalization errors; live source proof's noncanonical hash, corrected to canonical JSON; union assertion/type import-cycle gate failures. Stable suite attempt1 was deliberately stopped before those source changes and remains incomplete (exit -15). The later full result is reported separately. Reviewer findings on altered replay and zero-row CAS were fixed and tested, with original notes retained.

Full suite attempt2 completed with one obsolete status-wording assertion (6,650 passed, 476 skipped, exit 1). The follow-up fixes that assertion without changing the refusal rules. A separately recorded negative preview probe showed that an unavailable item could be described unconditionally as failed/no-retry; preview consequences now depend on availability. The normal unclosed_legacy runtime regression confirms a new current reference already works before closure, while the original failed record/approval remain unchanged. These are in ae96fb0.

Existing admission time remains selected after the accounting writer lock. Existing nondecreasing/sufficiently synchronized cooperating-process clock assumptions remain limitations; this work neither changes the inclusive rolling query nor tests arbitrary clock drift. New producer evidence requires updated/restarted workers for future work; never execute a preserved blocked queue to manufacture it.
