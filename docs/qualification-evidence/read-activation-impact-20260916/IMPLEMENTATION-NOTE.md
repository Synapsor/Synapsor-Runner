# Read activation impact preview

Reuse the exact runtime dependency predicate with a read-only projection of the candidate digest replacing the same-named active Read. Keep other active Reads. Load the real active Action authority in report mode; do not rewrite its registry or derive field-level dependency exceptions. Distinguish newly unavailable outcomes from ones already unavailable. Every affected outcome is listed with Action recheck then writer-review guidance.

All impact metadata and text remain outside canonical review bundles, activation digests, signed decision envelopes and execution configuration. Operator warnings do not grant authority or automatically recheck Actions. On an unreadable Action snapshot, report an unavailable assessment instead of claiming no impact or introducing an unrelated activation blocker. No provider call or source query is necessary.

Interactive full/focused/conversation confirmations and noninteractive bundle export/headless activation must present the warning before activation. Inspect direct Workbench and instant entry points as well. Existing rejection and authority behavior remain the oracle.

Implemented routes:
- Focused manual and conversation Read review show the exact outcome list inside the confirmation context; disabled dependency preparation is not presented as activation.
- Direct terminal activation shows it before confirmation. JSON/review-file export and signed headless activation emit the warning on stderr. The latter also returns display metadata outside `active`; the canonical review bundle and operator signature payload stay unchanged.
- Workbench preview includes impact and warning lines. Its one-click and relationship shortcuts show these in a plain-text confirmation before submitting activation. The older two-button preview shows plain text before enabling activation. Quick Start reuses the notice; its normal Workbench availability already excludes existing active Reads/full review.
- No Action authority produces no warning. Unchanged digest and unrelated Read boundaries do not produce new pauses. Already-stale dependent outcomes are identified separately. An unreadable snapshot produces a sanitized unavailable assessment, not a claim of zero impact or a new activation gate.

`unavailableReadDependencies` is exported with a minimal read-only structural input type. Its comparison and all runtime callers retain the same behavior. A projected candidate supplies its actual candidate digest, source and generation-lock fingerprint; it does not fabricate an activation record. Unaffected Read authorities remain in the projected set.

This is a current-state preview, not a transaction or a coordination guarantee. Concurrent authority changes can make a preview stale. No new locking, pinning, policy digest, execution binding, recheck, worker, permission or model tool was added. Rechecking Actions and writer review remain explicit operator operations.
