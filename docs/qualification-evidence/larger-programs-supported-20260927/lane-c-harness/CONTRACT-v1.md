# Lane C harness draft contract (qualification infrastructure)

This version is supplied for independent inert challenge; it is **not** a paid preflight signoff. Runner candidate f20e8633b352528fe216adfca6ca45a47a351e27 remains unchanged. Main inference calls are zero. The two DERIVED approval records in the Main test output are explicitly synthetic and cannot be used for either real journey.

The adapter retains the complete hash-checked closed historical financial ledger, uses its existing exclusive lock, and records new request-specific reservations in one appended Lane C namespace. Historical top-level totals are preserved as history; `summary()` computes current totals from the baseline plus the namespace. It does not settle an unknown cost, refund an attempt, or change Runner state. Monetary admission is cumulative campaign $60, combined journeys $40, each journey $20. Reservations and started calls count against each journey's 400 ceiling; failed/uncertain sends remain counted and held. At most two explicitly attributed transient retries may be reserved/started. The proxy itself performs no retry. Invocation/request IDs must be new; restart cannot clear an old hold. This is not a new product budget manager.

Independent immutable Main and Tester approval records bind to an unsigned exact plan hash (avoiding circular signatures). The final request body is checked after encoding and forwarded unchanged. It rejects changed model, tool/root mode, privacy routing, output stage caps, request bound, and declared provider flags. Known tool-free narration has its own unchanged stage cap. Existing product schema/whole-report/currentness validation remains authoritative; this harness does not replace it.

Actual token accounting, output billing bound and retained-resource admission are mandatory externally established hooks, bound to the exact final body. DERIVED synthetic hook values in the test are only test fixtures. A count RPC must have independent consent, monetary reservation and explicit counter accounting. The owner decision whether count RPCs share the 400 ceiling remains pending; this prototype supplies no implicit exclusion or hidden 200-inference ceiling. No actual source token count or provider inference is authorized by this draft.

OpenRouter output normalization is not assumed identical to direct OpenAI. `max_tokens` alone is not asserted to bound billed output for every eligible route. The hook must establish a conservative output bound; missing input/output/profile evidence stops before inference. Tariffs take the maximum of eligible request-specific prompt/cache-write/completion rates and applicable long-context overrides. Complete direct usage produces a tariff upper held as **not settled**; unknown usage/cost retains the full original reservation. A known cost above reservation is recorded honestly and stops admission, never capped in the ledger to manufacture compliance.

Exact request/response bodies are privately captured; safe views reuse the existing private-continuation redactor. Keys are caller-supplied only in the designated tester process and are never discovered by this module. The proxy has no database, writer, business callback or project mutation surface. Test controls use loopback with synthetic upstream forwarding. Actual activation still requires privacy, resource, restoration, route/token/cost, consent and funding preflight and the existing independent verdict.

Known remaining acceptance scope: independent inert challenge; actual count RPC counter policy; exact OpenRouter input/output accounting mechanism; actual resource fit with PG/WAL/captures; final sealed plan/envelopes and faithful installed integration. Local tests do not establish provider admission or whole-model workflow feasibility.
