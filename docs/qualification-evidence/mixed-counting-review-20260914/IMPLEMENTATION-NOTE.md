# Component association design — before product changes

The old `draft_paths` restriction is deliberate. It makes a counting comparison incapable of discharging a mixed paragraph by refusing the entire paragraph. Both unchanged saved replies reproduce support mismatch first; a separately recorded support-only derivation then reproduces the broad approval-pointer refusal. These are representation failures, not new owner ambiguity. Case A remains conditional and the assisted program remains exact, with absent filters.

Narrow the restriction at the comparison boundary, not at the whole-review verdict. Add host-only component attachments to existing passages. Each typed counter requirement must have its own exact root, source span, prior scoped interpretation and actual accepted clarification. Where the existing host context provides exactly one such interpretation, associate it as HOST-RESOLVED independently of the paragraph citation. An optional explicit counter support reference must match that exact decision; wrong explicit references are never repaired. No textual similarity, guessed source line, message index constant, or fixture phrase is used.

Preserve the submitted passage/paragraph support and each component's source requirement, accepted decision, concrete predicate, full configured limit, current domain and dependency digest. The broad approval pointer remains ordinary context and cannot prove a counter: each typed path still needs a referenced narrow counting root. Multiple counters may bind different exact decisions; grouping and ordering do not change the comparisons. Revalidate host attachments when loading; never accept serialized host proof as authority.

A mixed passage retains its original disposition, interpretation, topic, next action and residual checks. Counting equivalence cannot discharge a numeric maximum, window, stage/eligibility condition, privacy, effects, deployment readiness, external obligation or new contrary source claim. Existing scalar/field checks and disposition/readiness checks continue unchanged. Only an exclusively counting passage can use the previous narrow conflict-to-implemented normalization; mixed conflict remains conflict even when its counting components succeed. This deliberately avoids general prose splitting or claiming that reference validity proves all prose.

The established runtime gate → authority mutex → store read order, complete proposed/current/retained-history evidence, provider-outside-locks, source CAS and revalidation before persistence/reuse remain. Audit dependent review/publication paths for stale domain reuse; any required correction will stay within review invalidation, not runtime accounting. Missing storage is not empty history. Clock, inclusive window, automatic approval selection, runtime tools and selector guard are unchanged.

Diagnostics identify the specific component and distinguish support, ambiguity, broad references, typed mismatch, domain unavailability/staleness and genuine unequal counting. Correct evidence packaging without a new owner question or selector edit. Prompt/schema additions describe the same narrow contract only and will be recorded with exact before/after text tied to these two captured calls.
