# Receipt default input contract — implementation note

Baseline feecc2b and immutable 7b99cc6f verified. New actual installed reproductions independently reached writer/schema/table; preceding fields were explicit setup steps. Blank Enter returned without renewal in each; every 42-table/config/504-row snapshot equals the untouched start. Native receipt-orchestration through the actual Action adapter fails three corresponding assertions before repair. Historical delivery only executed writer; schema/table findings are new, not backdated.

The low-level readline callback produces an empty string for submitted blank/whitespace and undefined for Escape/end/error. The Action text prompter originally returns value || options.defaultValue; absent structured default merges submitted blank into cancellation. The receipt session adapter did not carry a text default option; prose was not executable data.

Now the existing session prompt options include an optional string default. Receipt writer/schema/table populate it; the Action adapter forwards it; the direct boundary adapter displays/forwards it; the conversation adapter displays it through its existing readAnswer default presentation. Only the submitted trimmed-empty callback accepts a supplied default. Cancellation never falls back. Nonempty input and no-default empty submission go unchanged to normal validation. No default is scraped from prose. Readline SIGINT/close are explicitly cancellation and listeners are cleaned up. Existing trimming remains; a whitespace-only submitted field uses its displayed default, invalid nonempty references/identifiers still fail ordinary validation.

Direct Action/native boundary adapters share the same event contract. Conversation receipt prompts preserve undefined cancellation. Model-authored questions and onboarding job questions keep their prior behavior; they do not acquire receipt defaults. Confirmation controls receive no text defaults and remain default-decline.

The receipt flow also pins its pre-input Action/binding/epoch/prior revision to the ordinary preview, before presenting final review. Existing confirmation/CAS validation still runs again at save. This prevents old prompted values silently binding to a context replaced during input; it adds no transaction or policy state. Existing source_db/Runner-ledger compatibility, identifiers, maximum lengths and writer-reference grammar remain unchanged. Configuration/credential values still require live verification; text defaults and selection records are not writer proof or execution authority.

One fixture-harness setup attempt caught bootstrap Postgres Unix-socket readiness before the final post-init server. No rows/roles had been restored. Its failure is retained; TCP readiness and the same owned labeled container fixed the setup. No product timeout changed.
