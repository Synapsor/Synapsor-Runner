# Saved-review resolution coverage (pre-freeze)

This inventory covers the saved authoring/Review/Resume path only. The canonical validators decide whether a report is valid. `authoring-review-resolution.ts` plans a next operation from first-party typed findings; it never authorizes that operation or accepts part of a report. Each registered local handler rechecks actor, exact target and currentness. The model receives only scoped correction feedback; the operator sees the pending operation and safe code; runtime clients receive no local authority route.

The adopted structural legacy codes are an explicit finite allowlist in `authoring-review-resolution.ts`. New typed reasons must be in the exhaustive `reasonPolicy`, and a new untyped structural code outside that allowlist fails closed at `collectCoverageFeedback`. This is a migration boundary, not a claim to enumerate arbitrary exceptions in all Runner packages. Some old parser diagnostics still have untyped codes and remain in the explicit allowlist until converted. Runtime expiry, approval, dispatch, blocked-work closure and source execution refusals are outside this change.

`planCoverageResolution` records coexisting findings and unevaluated checks. It routes to an operator prerequisite before another provider call when source meaning is unknown; otherwise it permits scoped correction only when *all* findings are structural and eligible. `leave_pending` remains available even alongside a terminal diagnostic. A route may be offered without being invoked; only strict whole-report validation and coordinated persistence establish BUSINESS completion. The final encoded correction request and provider result have separate evidence and verdicts.
