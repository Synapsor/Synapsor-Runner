Six actual fault controls establish the shared connector impact. Anchored INSERT,
ordinary UPDATE, and the actual Luna seven-field plus offer-consumption structure
all commit their declared effects in both receipt modes. Withholding the observed
backend COMMIT response triggers an unhandled pg Client error and exit 1 before
the existing transaction code returns uncertainty. Outer witness exit 0 is not a
passing runtime control. All original Source effects and fixtures are preserved.

The first repair owns asynchronous errors throughout each native Pool/Client
lifetime. It retains the first connection failure without exposing arbitrary
database error text, lets native query rejection reach the existing transaction
classifier, and destroys a client after connection failure or an unknown Source
outcome. Idle Pool errors are owned after pg has removed the disconnected idle
client. No successful COMMIT is reclassified because cleanup later fails.
Existing BEGIN/COMMIT/ROLLBACK, locking, isolation, SQL and receipt mode remain
unchanged. Only acknowledged whole rollback may supply no-effect evidence.

Runner-ledger uncertainty must durably fence the original intent and must not be
completed from matching rows or an operator's assertion. The actual Luna mode has
no atomic Source completion receipt; it therefore remains unknown after this
repair. Source-db legacy receipts also lack a complete normalized job/result and
trusted destination binding. Prospective recovery may use the existing receipt
table and existing authorized reconciliation transaction only after independent
review of a versioned full binding. Missing, legacy, malformed, conflicting or
foreign proof stays unknown, including when a receipt is absent.

Recovery, if admitted, performs Source reads and local bookkeeping only. It never
calls APPLY, claims a Source receipt, mutates business rows, requeues work, resets
a lease or manufactures an expired actor. The existing authenticated RECONCILE
decision remains separate from APPLY. Product recovery implementation and cold,
wrong-binding, concurrent and interrupted-bookkeeping controls are still pending.
