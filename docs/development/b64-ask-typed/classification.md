## Model-produced typed surface already available

`app.explore_data` receives the existing `ExplorePlan` and returns the existing typed outcome. Catalog calls receive explicit resource/query/pagination arguments and expose reviewed metadata only. The gateway rechecks current scope, allowed fields, relationships, typed literals, result privacy, query and rolling budgets. Provider arguments do not become trusted tenant/principal inputs. `AskTurnResult.answer` remains untrusted model narration. `source_database_changed` derives from actual tool receipts.

No typed declaration currently binds an Ask question's meaning to a plan. `AskIntentCheckDecision` is a local preference (`balanced`/`boundary_only`), not evidence that English has been interpreted correctly. Adding a self-attested second intent wrapper would create a new protocol and still would not prove natural-language fidelity.

Proposed narrow replacement, awaiting Main/R1 contract direction: the existing model-produced tool call carries the interpretation; host logic checks the actual typed request/result against existing authority. Remove prose-driven selection, plan invention and host-generated semantic correction. Derive metadata/data/refusal status from actual tool traces. Never mark `question_to_plan_checked: true` merely because the preference is balanced. No new provider call or fallback. Existing malformed-plan syntax correction is a separate formal protocol and remains bounded. This intentionally changes old tests that assert the English classifier's behavior; such assertions need explicit retirement/counterparts, not hidden relaxation.

They do not interpret user prose. `assertModelFacingTool` 4708+ recognizes prohibited canonical tool-name syntax and prevents exposure, not owner business intent. - `post-activation-ask.ts`: exact outcome status categories, configured environment identifiers, menu/key choices, shell token escaping and input bounds remain. The `Run: ` notice-line prefix 441 selects a host-produced presentation line, not user intent. No natural-language question classifier was found in this owning file.
- `scoped-explore.ts`: allowed field/operator/function/method/time-bucket membership, authority fingerprints, identifiers, typed literal families from database type syntax 6094–6098, enum membership, ISO date/time grammar and answer ID format remain. These enforce the typed plan and inspected schema, not English interpretation. Database error redaction 6625–6627 removes secret/URL patterns; generic error text categories 6628–6629 affect only safe diagnostic wording and no retry/query authorization. Conservative exact-group review guidance 6512+ uses actual PK/scope/FK metadata plus reserved identifier convention; it never grants execution and needs explicit reason retained if edited.
- `ask-access-summary.ts`: typed privacy/field refusal codes, typed detail reason/operation, reviewed permission membership, exact resource identity, actual catalog-proven relationship paths, safe identifier and bounded label formatting remain. Operation strings such as `filter operator ` and ` time bucket` are host-produced formal error-detail grammar, not extracted from user prose. Reserved `id`/`_id` checks restrict review guidance; they cannot widen access.
- `analytics-shell-render.ts`: safe-terminal escaping, markdown table syntax, verified result rows, typed suppression, withheld-values redaction, plan/result semantics, result evidence and byte/width bounds remain. Label capitalization/pluralization/numeric display is presentation-only. `_id`/`name` formatting does not itself choose a query or grant permission; any use that selects a data operation must be retired.
- `boundary-catalog.ts`: reviewed field and operation membership, kept-out/withheld filtering, exact relationship proof, Mermaid escaping/identifier grammar and safe filenames remain. Pure label capitalization, pluralization and suffix removal format examples; no input prose is interpreted and no permission changes. Remove semantic measure ranking even though it only affects examples.
- `instant-first-value.ts`: first resource/measure/group from the typed reviewed candidate, explicit time-bucket membership and bounded top count choose a conservative existing plan. Regexes 85–111 only format its label/question after that plan is built. No incoming question classification or authority decision uses those words.
- `packages/mcp-server/src/scoped-catalog.ts`: Unicode normalization/tokenization, exact ID/name comparison and token posting intersections are bounded catalog retrieval, never plan authorization. Partial ranking identifies suggestions only; typed match kind/missing terms disclose uncertainty. Existing `unambiguous_id` decides inline metadata disclosure of a current authorized contract only, not intent or action eligibility. Preserve exact scope/session/cursor binding, byte/call/record budgets and current authorization projection. English stopwords are separable and should be retired.
