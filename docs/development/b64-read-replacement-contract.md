# Read replacement through the current native owner

This is an additive question mode under the current B64 authoring pin, not a new store, native envelope migration or model-completion format. Existing review/missing-answer records retain their meaning. Readers lacking the mode reject its strict binding; no unknown field is dropped.

A `replacement_answer` question names `review_question_id`, an exact earlier declined/cancelled grouped review. It retains that review's entire scope record, actual consumed completion, context and job scope. The native parser cross-checks those records and rejects another proposal, branching raw roots, or a changed origin. Its owner handoff is an ordinary user-initiated `read_revision_instruction` with **no completion**. The earlier review's genuine completion is provenance, not permission to acknowledge a new model response. Capture records exact raw words without confirmation or scope authority.

Raw replacements use their own predecessor chain. A new actual model result becomes a `review` successor of the original grouped review, not the raw question; therefore the new review can cite the latest genuine raw testimony without falsely retiring it. Older Yes is already declined and cannot revive. No synthetic unresolved model requirement, replay of a completed dispatch, counter reset, invented response or automatic final confirmation is permitted.

The producer continuation must hydrate the last actual spent controller state (call/answer counts, bounded correction, relationships, references and history), and distinguish this post-review continuation from an interrupted dispatch. It captures/resumes the user correction then sends only the next permitted model request, retaining exact original request/Source and bounded current host inventory. Blank/cancel remains pending; changed context, failed save or uncertain acknowledgment prevents egress. Returned mappings still require actual compiler analysis and a separately displayed grouped default-No decision.
